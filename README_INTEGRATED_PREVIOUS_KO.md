# SLYCE 3.3.0 · 통합 소스

이 ZIP은 `Source`, 빌드 설정, 80개 합성 보컬 대체 음원, 검사 코드가 함께 들어 있는 **단일 통합 프로젝트**입니다. 이전 UI 패치 → 음질 패치를 따로 적용할 필요가 없습니다. 원래 프로젝트와 별도 폴더에서 먼저 빌드하세요.

**상태: 배포 검증 전 통합 소스.** 실제 JUCE 전체 빌드·DAW 실행·청음·UI 캡처 검증을 끝낸 상용 설치파일은 아닙니다. 이번 환경에서는 SDK 다운로드가 되지 않아 제한적 대체 구현을 쓰는 네이티브 DSP/루퍼 검사까지 실행했습니다. 아래 검증 범위를 구분해 주세요.

## 1. 무엇을 통합했나

| 영역 | 반영 내용 |

원본 표기는 403 SOUNDS였지만 실제 소스의 악기 목록은 **429개**여서 데이터와 카운터를 429로 맞췄습니다. 악기별 이름/순서를 제거해 숫자를 맞추지는 않았습니다. 모든 악기를 귀로 듣고 개별 프리셋을 수작업 재설계한 것은 아닙니다.

## 2. 보컬 음원: 원본과 합성 대체 파일을 구분하세요

업로드된 소스 ZIP에는 원본 80개 WAV와 외부 악기 샘플이 없었습니다. 이 패키지의 `assets/fallback_vocals`는 이번에 수식 기반으로 만든 **보컬풍 합성 소리**입니다. 사람의 노래 녹음을 복원하거나 특정 가수의 목소리를 복제한 것이 아닙니다. 피치/포먼트 개선만으로 원본 사람 보컬을 다시 만든 것이라고 이해하면 안 됩니다.

- 80개, 파일당 4초, 44.1 kHz, 모노, 16-bit PCM입니다.
- 합성 파일을 사용하는 항목에는 브라우저에서 `[SYN]`을 표시합니다.
- 원본 파일을 프로젝트 `examples` 폴더에 같은 이름으로 넣으면 CMake가 **파일별로 원본을 우선 사용**합니다. 일부만 복구하면 나머지만 합성 대체 파일을 사용합니다.
- 원본 폴더는 `-DSLYCE_ORIGINAL_VOCALS_DIR="D:/SLYCE/original-vocals"`처럼 지정할 수 있습니다.
- 합성 대체 파일을 허용하지 않으려면 `-DSLYCE_ALLOW_SYNTHETIC_FALLBACK=OFF`를 사용하세요. 누락된 원본이 있으면 설정 단계에서 실패합니다.

`assets/vocal_asset_names.json`에서 필요한 이름, `assets/fallback_vocals/manifest.csv`에서 실제 파일 해시와 생성 정보를 확인할 수 있습니다. 원본 샘플을 보유하고 있다면 최종 제품에는 원본을 복구한 뒤 청음 비교하는 것이 적절합니다.

## 3. Windows에서 빌드

준비: Visual Studio 2022의 **C++를 사용한 데스크톱 개발**, Git, CMake 3.24 이상. 첫 빌드는 JUCE와 Signalsmith 의존 소스를 내려받으므로 인터넷이 필요합니다.

PowerShell에서 프로젝트 폴더로 이동한 뒤:

```powershell
.\BUILD_WINDOWS.ps1
```

또는 직접 실행:

```powershell
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release --target VocalChopStudio_VST3 VocalChopStudio_Standalone --parallel 4
```

생성 경로는 일반적으로 `build/VocalChopStudio_artefacts/Release/VST3`와 `Standalone`입니다. 이 폴더에는 컴파일한 결과만 생성됩니다. 기존에 설치한 VST3와 혼동하지 않도록 파일 시각/버전을 확인하세요.

## 4. macOS / Linux에서 빌드

C++17 컴파일러, Git, CMake가 필요합니다. macOS는 Xcode Command Line Tools, Linux는 JUCE가 사용하는 오디오/X11/OpenGL 개발 패키지가 필요합니다. 동봉한 CI 예시에 Ubuntu 의존 패키지 설치 단계를 넣었지만, **CI는 여기서 실행하지 않았습니다.**

```bash
bash BUILD_MAC_LINUX.sh
```

기본 산출물은 VST3·Standalone이며 AU는 macOS에서만 설정됩니다. Apple Silicon/Intel 또는 Universal 빌드는 본인의 배포 대상으로 별도 검증하세요.

### 이미 받아 둔 SDK 사용

```bash
cmake -S . -B build \
  -DJUCE_SOURCE_DIR=/path/to/JUCE \
  -DSIGNALSMITH_STRETCH_SOURCE_DIR=/path/to/signalsmith-stretch \
  -DSIGNALSMITH_LINEAR_SOURCE_DIR=/path/to/signalsmith-linear
```

JUCE는 8.0.4, Linear는 0.3.1을 기본 지정했습니다. Stretch 기본값 `main`은 변경 가능한 브랜치입니다. 재현 가능한 정식 릴리스를 만들 때는 `SIGNALSMITH_STRETCH_TAG`에 실제 검증한 커밋을 고정해야 합니다. 로컬 Linear 폴더는 `signalsmith-linear`라는 이름으로 두면 상위 경로 include와 호환됩니다.

| CTest 네이티브 검사 | 5/5 스위트 통과 | 아래 코드·수학·버퍼 동작 검사이며 플러그인 전체 빌드가 아닙니다. |

`tests/local_shim`은 검사를 위한 제한적 대체 구현입니다. JUCE 리버브/디코더 등을 실제 SDK처럼 검증하지 않습니다. 제품 빌드에 이 폴더를 include하면 안 됩니다. 전체 악기 행렬은 공통 합성 엔진을 검사한 것이며 플러그인 전체 이펙트 체인, 모든 제어 조합, 모든 외부 SFZ까지 검증한 것이 아닙니다.

오프라인 핵심 검사 재실행:

```bash
cmake -S . -B build-tests -DSLYCE_TESTS_ONLY=ON -DSLYCE_BUILD_ENGINE_TESTS=ON -DSLYCE_TEST_LOCAL_SHIM=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build-tests --config Release --parallel 4
ctest --test-dir build-tests -C Release --output-on-failure
python -m pip install -r tools/requirements.txt
python -m unittest discover -s tests -p 'test_*.py' -v
python tools/check_source.py
```

원본 로그와 CSV는 `reports`에 있습니다. `.github/workflows/build.yml`은 사용자 환경에서 실제 SDK 빌드를 시도하도록 제공하는 설정이며, 동봉되어 있다는 이유로 CI 통과를 의미하지 않습니다.

## 6. 루퍼 사용 시 알아둘 정책

**SYNC는 메트로놈/새 녹음 길이의 BPM 연동입니다.** 기존 루프를 다른 템포로 늘이거나 줄이는 타임스트레치, DAW의 모든 재생 위치 이동을 따라가는 완전한 transport sync는 추가되지 않았습니다. UI를 닫아도 BPM 반영은 프로세서에서 처리됩니다.

Free 또는 1/2/4/8마디로 새 녹음 길이를 선택할 수 있습니다. 루프 1개의 최대 길이는 30초입니다. 서로 다른 길이 파일을 합칠 때 공통 반복 주기로 Export하며, 기본 공통 길이가 120초를 넘으면 잘라서 성공시키지 않고 거부합니다. 예를 들어 2초/3초 루프는 6초로 내보냅니다. STEM은 같은 스냅샷·길이·공유 감쇠량으로 내보내 위상과 상대 음량을 유지합니다. 매우 큰 Export에는 메모리와 시간이 필요합니다.

동시 접근을 개선하기 위해 페이지 참조 스냅샷과 사전 할당 버퍼를 사용했습니다. 다만 렌더링/스냅샷에는 짧은 상호 배제 구간이 남아 있습니다. 따라서 **완전 lock-free 오디오 엔진이나 지연 없는 대규모 부하를 보장하지 않습니다.** 높은 샘플레이트에서 여섯 트랙·Undo 버퍼·상태 복사를 쓰면 메모리 사용량이 커집니다.

## 7. 상태와 호환성

DAW 상태에는 편집 샘플 PCM과 루프를 포함하므로 기존보다 프로젝트가 커질 수 있습니다. 샘플 상태는 128 MiB 상한 및 유효성 검사를 두었습니다. 기존 파라미터 상태를 읽는 경로는 유지했지만, 모든 과거 버전/호스트 프로젝트와의 호환성은 아직 실제 시험하지 않았습니다. 별도 프로젝트 사본에서 확인하세요.

외부 SFZ와 그 음원은 파일 경로에 의존합니다. 이 ZIP에 원본 SFZ/녹음 악기 라이브러리가 들어 있지는 않습니다. 누락된 외부 파일을 새롭게 복원한 것으로 보지 마세요.

MIDI 서스테인 CC64를 정상적으로 쓰도록 루퍼 Undo는 **CC80–85**로 옮겼습니다. 기존 컨트롤러 매핑을 쓰고 있다면 갱신해야 합니다. 루퍼 Main CC20–25, Stop CC40–45, 재녹음 CC50–55는 유지합니다.

피치/포먼트 및 리미터의 지연 보고를 프로세서에 연결했지만, 설정 전환과 호스트 보상 반응은 실제 DAW에서 검증하지 않았습니다. 전환 시 연주 타이밍과 클릭/무음이 생기는지 확인하세요.

## 8. 테마와 디자인

`design/reference_light.png`, `reference_dark.png`는 사용자가 제공한 **디자인 기준 이미지**입니다. 이번 앱을 실행한 캡처가 아닙니다. 두 테마의 색상·배치·파형 카드·FX 패널·건반 구조를 코드에 반영했지만, 렌더링 결과를 겹쳐 비교한 픽셀 단위 일치는 보장하지 않습니다. 실제 기능과 데이터에 맞추느라 카운터 429 및 `[SYN]` 등의 표시는 참고 이미지와 다릅니다.

LIGHT/DARK 전환은 하단 버튼이나 테마 메뉴에서 합니다. 기본 앞면을 복잡하게 하지 않으면서 기능을 없애지 않도록 상세 합성/FX/모션 설정은 SOUND DETAILS 패널에 배치했습니다.

## 9. 데모 / 정식 빌드

소유자의 기존 활성화 흐름과 기본 라이선스 API 주소는 유지했습니다. `SLYCE_DEMO_GATE=ON`이 기본값이며, 미활성화 데모는 60초마다 2초를 음소거하고 상태 저장은 허용하도록 변경했습니다. 정식 배포/테스트 정책은 본인이 점검하세요. 활성화 성공·실패·오프라인 동작을 여기서 실제 서버와 검증하지 않았습니다. 비밀 라이선스 키를 새로 생성하거나 넣지 않았습니다.

JUCE/Signalsmith 등 타사 코드의 사용 조건은 제품 활성화와 별개입니다. `THIRD_PARTY_NOTES.md`를 확인하세요.

## 10. 배포 전에 반드시 완료할 항목

`RELEASE_CHECKLIST_KO.md`의 실제 컴파일·DAW 저장/복원·샘플레이트·부하·테마 확인·청음 항목을 진행하세요. 이 패키지는 수정된 소스를 하나로 모은 전달본이며, **오류 0개 또는 청음 완료를 보증하는 배포 인증서가 아닙니다.**
